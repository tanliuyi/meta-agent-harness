# Desktop 智能体设置需求与实现边界

状态：已实现（2026-09-10 定点集成验证通过）

实现范围覆盖用户级 CRUD/CAS/default、两个新会话入口的选择与过期处理、会话快照持久化/恢复/分支/worker replacement，以及提示词、工具白名单和可配置内置插件的创建前运行时装配。

当前明确限制：

- 设置页中的工具/内置功能目录是静态候选目录；项目和会话当下的可用性在草稿解析后展示，设置页本身不执行按项目解析。
- 提示词来源预览目前展示来源类别与 included/excluded/dynamic 状态，不展开自动发现文件的完整基础提示词正文。
- “完全替换”只保证替换基础提示词与自动发现的 SYSTEM/APPEND；插件动态上下文和运行上下文仍可加入，不保证 provider payload 与输入逐字相等。
- 关闭记忆只约束该主会话及 Desktop native 子执行者的记忆装配，不创建私有记忆库，也不阻止其他会话索引既有历史。
- 现有会话不支持运行中切换或应用模板最新 revision；旧的无快照历史继续使用旧行为。

## 1. 已确认的目标

在 Desktop 设置中增加“智能体”菜单，提供一个内置默认智能体，支持创建和配置自定义智能体：

- 系统提示词，必须允许完全替换；
- 启用的工具；
- 启用的内置插件，例如子智能体、记忆、自动标题。

本文其余产品行为为结合现有代码补全的建议，不表示用户已经逐项确认。这里的智能体是主会话的可复用配置；现有“子智能体”是委派任务的执行者，两者不共用同一份定义。

## 2. 实现前代码事实

本节记录方案形成时的基线，用于解释后续实现选择，不代表当前实现状态；当前状态与限制以上文状态说明和定点测试为准。

| 链路 | 当前行为 | 对需求的影响 |
| --- | --- | --- |
| 设置导航 | `src/renderer/src/features/settings/settings-page.tsx` 已有记忆、子智能体、自动标题等独立页面 | 新增智能体管理页；插件详细参数继续由现有页面管理 |
| 主会话创建 | `src/main/pi/session-runtime.ts` 创建 services、加载扩展后创建 AgentSession，显式传入 model/thinking；未传智能体提示词或工具选择 | 配置必须在资源加载与会话创建之前解析，不能创建后再补设 |
| 草稿配置 | `src/main/pi/session-configuration.ts` 通过 metadata 资源加载返回模型、命令、插件信息；不创建真实 AgentSession | 增加智能体选择后，草稿和真实会话必须使用同一套解析规则 |
| 工具选择 | `../coding-agent/src/core/sdk.ts` 支持 `tools`、`excludeTools`、`noTools`；`agent-session.ts` 将 allowlist/denylist 用于工具注册表 | 可以复用持续生效的 SDK allowlist，避免仅修改当前 active tools |

| 文件指令 | `../coding-agent/src/core/resource-loader.ts` 分别发现 SYSTEM.md、APPEND_SYSTEM.md 和上下文规则文件 | 完全替换必须显式清除自动发现的 SYSTEM/APPEND 来源，不能遗漏 APPEND |
| 插件指令 | 记忆与 `run-code-tool.ts` 在 `before_agent_start` 中追加提示词 | 必须区分基础提示词、可选上下文、已启用插件的动态注入 |
| 内置装配 | `desktop-builtin-provider.ts` 返回内置 factories；`desktop-extension-runtime-policy.ts` 对 factories 包装，不会因 entry 缺失自动过滤 factory | 必须同时过滤元数据、factory、skills、工具与方法注册表 |
| 插件调用 | 内置浏览器等通过 `run_code` 方法表提供能力，不能仅按直接工具名处理 | run_code 的方法表及其说明必须只包含当前会话有效插件 |
| 插件参数 | 自动标题有全局 `enabled`；`memory-settings-contracts.ts` 没有统一 enabled，仅有复盘、纠错、写回等开关 | 不应虚构所有插件都已有全局总开关 |
| 记忆范围 | 记忆插件使用全局/项目存储；还会扫描全局 sessions 目录建立索引 | 关闭本会话记忆不等于该历史永不被其他会话检索，也不创建智能体私有记忆库 |
| 子执行者 | `desktop-child-session-factory.ts:100` 固定传 `extensionProfile: ["provider", "memory", "runtime", ...]` | 主会话关记忆不会自动影响 native 子执行者，必须显式传递策略 |
| 插件选择持久化 | 现有 `enabledPluginIds` 进入 Desktop 摘要索引；`session-metadata-index.ts:364` 起的重建只保留旧 updatedAt，未恢复此字段 | 存在重建丢失选择的路径；智能体快照不能仅存于可重建索引 |
| 会话身份 | `Thread.agentName` 表示现有 subagent 身份，提升为根会话时会清除 | 主智能体模板身份必须使用独立字段 |
| 新建入口 | 主页面与侧栏均有草稿；侧栏目前使用父项目/cwd，再加载项目默认配置 | 两个入口都需要智能体选择，区分普通子会话与自动委派执行者 |

本次为需求相关链路审查，不是整个 Desktop 的全面缺陷审计；现有规范中的旧架构描述以当前源码为准。

## 3. 产品范围

### 3.1 管理与入口

设置增加 `/settings/agents`。列表展示名称、描述、是否内置、是否为新会话默认选择。支持新建、编辑、复制、删除、设为默认；内置“默认智能体”不可删除，允许编辑和恢复出厂配置。

“内置默认智能体”是固定条目；“新会话默认选择”是指向某个条目的偏好，两者分开存储。删除被设为默认的自定义智能体后，新会话默认选择回到内置条目。

首版配置为 Desktop 用户级，所有项目可选，不增加项目级同名覆盖和同步/分享功能。

### 3.2 新会话使用

- 新会话草稿增加智能体选择器，与现有项目、模型、思考级别选择并列。
- 选择智能体、项目或查看配置不得创建真实会话。
- 切换智能体保留输入和附件；重新解析工具、插件和命令，不自动覆盖用户选择的模型。
- 第一次发送时，原子绑定已选择的智能体配置，禁止先按默认配置启动插件再修改。
- 提交期间锁定选择；重复发送沿用现有 single-flight 处理。
- 已有会话展示创建时使用的智能体名称及配置详情。首版不提供会话内切换智能体或应用智能体最新版本。
- 侧栏手动新建的普通子会话也显示选择器，建议默认继承父会话的智能体快照，允许发送前改选；即使父模板已删除仍可沿用快照。这与子智能体插件自动委派的执行者不同。

### 3.3 默认行为

默认智能体的初始行为保持当前 Desktop 的提示词来源、工具默认值和内置功能，不强制覆盖用户现有 SYSTEM.md 或 defaultTools 设置。

配置需要区分“使用当前系统默认值”和“显式选择”。自定义工具选择不得把空列表当成未配置；内置默认行为也不能通过空列表表示。

新增自定义智能体可从默认配置复制，但必须展示将保存的选择。产品升级新增可选内置插件或工具，不应静默加入已有自定义配置。

## 4. 系统提示词

### 4.1 模式

建议使用三种明确状态：

| 模式 | 行为 |
| --- | --- |
| 使用系统默认 | 保持 Desktop 当前默认提示词解析规则 |
| 追加 | 在当前基础提示词和既有 APPEND 内容之后追加用户文本 |
| 完全替换基础提示词 | 使用用户文本替换默认编码助手提示词，以及自动发现的 SYSTEM.md、APPEND_SYSTEM.md 内容 |

“完全替换”必须真实去除默认角色、编码助手要求和默认行为指南。禁止用追加自定义角色的方式模拟替换。

用户文本按字面字符串处理，即使内容恰好是一个存在的文件路径，也不能读取该文件作为提示词。首版建议完全替换模式拒绝全空白文本，给出表单错误；不能接受空文本后静默退回默认编码助手。

### 4.2 额外上下文

建议在高级区域独立提供：

- 加载全局规则；
- 加载项目规则；
- 提供技能目录。

“规则”包括当前 loader 支持的 AGENTS.override.md、AGENTS.md、CLAUDE.md 等文件及既有优先级，不能只过滤名为 AGENTS.md 的文件。

建议首次选择完全替换时，默认不继承全局/项目规则和既有 APPEND 内容；用户可显式启用规则。技能目录可独立保留，并注明现有 Pi 默认只在 `read` 可用时把技能目录写入提示词。切换模式不清空文本，界面清楚展示当前选择。

技能控制必须覆盖默认发现、Desktop 附加技能路径以及插件 `resources_discover` 补充的目录。不能只设置 `noSkills` 就声称技能注入已关闭。关闭目录展示不必卸载用于校验插件完整性的技能资源；资源存在与模型可见需要区分。

### 4.3 插件与运行上下文

已启用的插件仍可加入其说明或动态上下文，例如记忆策略和 run_code API 说明；工作目录等运行上下文单独展示来源。这些内容不属于被替换的默认角色提示词。

因此界面文案使用“完全替换基础提示词”，并在下方明确展示“仍会加入的内容”。不能一边显示“最终仅发送你的文本”，一边隐式加入插件策略。

若后续要求最终系统消息逐字等于用户输入，应单独引入严格模式，并处理所有插件提示词 hooks 和 provider payload 改写；本方案不宣称已提供这个额外保证。

### 4.4 可查看的实际配置

首版至少提供只读的基础提示词预览和来源清单：系统默认/用户文本、APPEND 文件、全局规则、项目规则、技能、插件动态注入。

草稿预览不得为了显示内容调用模型或运行学习/标题任务。动态记忆等内容可标为“发送时生成”。会话诊断可展示最近一轮 Pi 组装后的 system prompt，但不能称其为完整 provider 请求：`before_provider_request` 还可能改写 payload，工具 schema 和历史消息也不在这段字符串内。

## 5. 工具配置

### 5.1 选择语义

- “工具”定义为主会话模型可直接调用的工具。
- 列表按来源分组，至少区分基础工具、内置插件工具、其他已加载扩展工具；展示名称、简述和来源。
- 基础候选来自现有 Pi 工具目录，包括 read、bash、powershell、edit、write、grep、find、ls；不能只把当前默认四个工具当成全部候选。
- 支持显式空列表，表示模型不调用任何工具；也允许保留自动标题等后台插件。
- 显式配置使用白名单。未选择的工具在首次发送、动态注册、资源 reload、恢复会话后均不能重新成为可调用工具。
- 插件关闭时，其工具标记为不可用；保存时不要因勾选工具自动重新启用插件。
- 关闭工具不自动关闭所属插件的后台行为；界面提供插件开关入口。
- 已保存但暂时不可用的工具保留 ID 和不可用原因，不静默替换成其他工具。

工具名单是模型调用配置，不是文件系统只读或 OS 权限边界。保留 bash 时，关闭 write 不代表禁止写文件。

### 5.2 run_code

run_code 是统一调用入口，插件方法不作为同名直接工具混入基础工具列表。首版按插件粒度控制方法，不增加逐方法权限编辑器。

- 有效方法表只包含允许加载的插件；关闭内置浏览器后不能通过 run_code 调用它。
- run_code 关闭后，不应继续向模型注入其生成 API 说明。
- 方法表为空时不展示无可用能力的 run_code 入口。
- 第三方插件继续使用现有安装/项目/会话启用机制；本需求不替换这些机制。若 run_code 保留，界面应能看到它当前能访问哪些第三方插件。

### 5.3 子智能体边界

主智能体配置与子智能体定义分开。首版不要自动把主提示词复制成所有子智能体的提示词，也不要复用主智能体名称作为子智能体 registry key。

主会话的工具名单只限制主模型直接调用；委派执行者仍使用现有子智能体配置。界面在启用子智能体时说明这一点，不能把主会话的少量工具选择包装成对全部子任务的权限保证。

建议将主会话关闭记忆作为 Desktop native 子执行者的上限：子执行者继续使用自己的提示词和工具配置，但不得因当前固定 extensionProfile 重新加载记忆，也不得经单独的 memory injection 路径注入。开启记忆时仍采用现有子执行者配置。该规则需覆盖嵌套启动、恢复和 fork 上下文；它不删除历史消息中已经出现的记忆内容，也不形成全局历史索引排除。

外部 CLI 执行者有独立提示词和工具机制，Desktop 不能假定其记忆开关会约束对方，应明确显示“使用外部执行者配置”。本规则只控制 Desktop 自己启动的 native 记忆能力。

## 6. 内置插件配置

候选应来自独立的可配置内置功能元数据，当前至少涉及：记忆、子智能体、自动标题、Goal、浏览器。Checkpoint History 是否可关闭需要结合撤销入口决定，不应仅因它在 registry 中就直接暴露开关。

模型服务商注册、消息投影、工具执行等基础设施不作为普通插件让用户关闭。registry 中同时存在 provider 与功能插件，必须明确分类。

关闭的语义是：不运行该会话中的插件 factory、事件处理、命令、提示词注入、工具与方法注册，也不启动其后台任务。设置页面本身仍可访问，既有数据不删除。

| 插件 | 关闭后的预期行为 |
| --- | --- |
| 记忆 | 本会话不注入记忆、不提供记忆/技能管理/历史检索相关工具、不启动其复盘/纠错/写回/索引 hooks；不删除历史记忆 |
| 子智能体 | 不提供委派入口、相关命令和插件指导，不为本会话启动委派工作 |
| 自动标题 | 不调用标题模型；保留从首条消息提取标题和用户手动改名 |
| 浏览器 | 不向本会话提供浏览器方法与相关插件说明；用户手动浏览器界面是否保留按现有产品入口处理 |
| Goal | 不提供 Goal 工具和命令；会话控制面的 Goal 操作应反映不可用状态 |

已有插件参数继续由其原设置页管理：自动标题全局 enabled=false 时会话无法启用标题生成；记忆的复盘/纠错/写回等开关继续控制相应行为。没有全局 enabled 的插件，不为统一 UI 而凭空增加第二个总开关。

智能体页面显示“配置为启用”和“当前实际可用”的区别，并说明阻止原因。调整一个智能体不得修改全局插件设置或影响另一个同时运行的会话。

## 7. 记忆与数据范围

首版沿用现有用户级和项目级记忆，不按智能体 ID 创建新存储目录。

关闭智能体记忆，仅停止该会话运行记忆插件。其他启用记忆的会话或用户手动索引仍可能读取其普通 JSONL 历史；现有记忆插件会扫描历史目录。不得用“隐私会话”“从不记录”描述这个开关。

如要禁止后续被检索，需要独立的会话索引排除标记，并让历史回填、实时索引、手动索引和搜索过滤全部遵守，同时定义已有索引如何删除。这属于额外需求，不由本次功能开关隐含实现。

## 8. 保存与会话生命周期

### 8.1 配置保存

采用现有设置服务模式：main 持有配置、校验输入、revision/CAS 检测冲突、原子落盘。提供稳定 ID 与 revision，名称只用于显示。保存失败保留表单；其他窗口修改时不能覆盖未保存内容。

保存智能体不创建会话、不调用模型、不启动插件后台工作。

### 8.2 会话配置快照

首次创建会话时保存智能体 ID、名称、revision 和有效配置快照；快照不参与 LLM 对话消息，不保存凭据、可执行插件路径或插件完整二进制。

快照必须有可独立于摘要索引恢复的权威存储，索引仅保存投影。现有索引重建未保留 `enabledPluginIds`，不能照搬该独占存储方式。可以评估版本化 Pi custom entry 或专用会话元数据，但必须验证首条回复前的可靠落盘、崩溃恢复和分支截断；不能仅凭 appendCustomEntry 调用成功就假定已持久化。

快照固定的是主提示词文本/模式、上下文选择规则、工具选择和内置插件选择，不冻结项目文件内容、动态记忆、模型、第三方插件版本或现有全局插件参数。界面不能承诺升级后逐字复现历史请求。

- 修改/删除智能体不重写已有会话快照。
- 重启、崩溃恢复、后台继续运行和分支会话使用已有快照。
- 分支应继承分支来源的配置，即使分支点早于普通 custom entry，也不能丢失配置后回退为默认。
- 外部发现或未来导入带快照的历史时，只接受声明式、可验证配置，重新验证当前资源；未安装插件不自动安装。当前 Desktop 没有用户导入会话入口，本需求不新增该入口。
- 无快照的历史保留当前旧会话行为；不能套用用户此刻设定的新默认智能体。可在首次打开时建立标明来源的旧行为快照，但不得声称还原了历史提示词。
- 快照损坏返回明确错误，禁止自动启用全部工具/插件作为恢复方式。

现有 Desktop 插件更新/apply 流程仍可替换 worker。replacement worker 必须重新叠加原智能体快照，不能因插件更新丢失工具限制。全局插件参数保持现有刷新时机，本需求不额外承诺实时应用。

### 8.3 草稿竞态

草稿选择记录智能体 ID/revision 及当前扩展 generation。第一次提交时由 main 重新校验；若配置已变化、被删除或可用资源已变化，在创建 worker 前返回明确过期状态，刷新配置并保留输入/附件，不静默改用另一个智能体。

现有 createRequestId 的幂等语义必须保留：同一已提交请求重试返回原会话及原快照，不能因模板后来变化而重新创建。创建尚未提交且用户更换选择时使用新的请求身份，避免旧 reservation 与新配置混用。

## 9. 实施分层

建议复用现有架构，新增一份主智能体配置模型和统一解析入口：

1. shared：智能体定义、工具目录、保存结果、会话快照与草稿选择契约。
2. main 设置服务：CRUD、默认选择、revision 校验与持久化；renderer 不解析文件。
3. 统一 resolver：组合智能体选择、项目/全局资源可用性，生成声明式运行配置；草稿和真实会话共用。
4. sidecar：创建 services 前应用提示词/上下文策略，按有效集合筛选 factories/skills/方法表；创建 AgentSession 时传 SDK 工具白名单。
5. 会话存储与 worker：持久化并传递快照，覆盖新建、恢复、分支和 replacement。
6. renderer：设置页、草稿选择器、当前会话配置详情和不可用原因。

必须先核对 tool catalog 的获取边界：元数据阶段可获取静态工具，session_start 或后续动态注册的工具不能通过创建隐藏会话发现。保留稳定标识和不可用状态，不以一个时刻的 active tools 作为全部配置目录。

无需为此另建 Agent loop、插件执行器、全局环境变量切换或 per-agent auth/models 目录。

## 10. 验收场景

| 场景 | 必须满足 |
| --- | --- |
| 创建/复制/删除/默认选择 | stable ID、默认回退及编辑冲突正确，内置默认条目不可删除 |
| 草稿切换智能体 | 不创建 SessionManager/AgentSession，不丢失输入附件，命令与能力随选择更新 |
| 完全替换 | 默认编码助手要求及自动发现的 SYSTEM/APPEND 不再出现；可选规则按开关处理 |
| 文件路径文本 | 填入现有文件路径，模型接收到该字符串，未读取文件内容替换它 |
| 替换空文本 | 按明确的校验规则拒绝；无静默默认回退 |
| 技能与插件指令 | 关闭目录后不能经 resources_discover 再注入；禁用插件无残留指导；预览来源准确 |
| 仅启用 read | 主模型只能调用 read；动态注册和 reload 不重新启用其他工具 |
| 空工具列表 | 主模型工具 schema 为空，允许独立保留自动标题 |
| 关闭浏览器但保留 run_code | 浏览器方法在注册表中不存在，不能仅靠隐藏说明实现 |
| 关闭 run_code | 不注入其 API 说明；其他独立插件后台功能依其开关运行 |
| A 开记忆、B 关记忆 | B 不运行记忆 hooks；A 不受影响；界面不承诺 B 历史不能被索引 |
| 关闭自动标题 | 无标题模型调用；首条消息标题及手动改名可用 |
| 关闭 Goal/子智能体 | 工具、命令和对应控制入口一致反映不可用 |
| 修改或删除会话来源智能体 | 历史恢复和分支保留原配置，名称来源可辨认 |
| 插件 apply/replacement | 原智能体限制保持；失败回滚也保留选择并向用户显示回滚结果；同一 session 不同时出现两个 writer |
| 删除/重建摘要索引后恢复 | 智能体快照与显式空集合不丢失，不扩大工具/插件集合 |
| native 子执行者记忆继承 | 父关闭记忆时，native 子执行者不加载/单独注入记忆；外部执行者配置边界明确 |
| 侧栏普通子会话 | 默认继承父快照、可提交前改选；不与自动委派执行者混淆 |
| 创建重试 | 同一已提交请求返回原会话与原快照，配置更新不制造第二个会话 |
| 草稿配置被其他窗口修改 | 提交前发现 revision/generation 过期；无错误配置 session，无输入丢失 |
| 旧历史、损坏快照、缺少资源 | 明确区分旧行为与错误，不回退成全能力智能体 |

实现验证使用现有 faux provider/定点测试核对实际 system prompt、工具 schema、factory/hook 调用次数和恢复后的配置。无需使用真实模型或付费 token。代码实现后运行对应测试及根级 `npm run check`。

## 11. 实现前的剩余产品选择

建议按以下默认方案推进设计；这些项仍需与产品取舍保持一致：

1. 替换定义：完全替换基础提示词，额外规则可选、插件注入可见；不宣称最终 provider payload 逐字等于用户输入。
2. 子智能体：主工具名单只限制主模型；建议关闭记忆同时约束 Desktop native 子执行者，外部执行者使用独立配置。
3. Checkpoint History：先保留系统行为，完成撤销入口审查后再决定是否列为可关闭功能。
4. 现有会话：首版固定智能体配置，不增加运行中切换或“应用最新智能体”事务。
